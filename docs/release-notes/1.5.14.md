# Zarya 1.5.14

## Optional release signing

- Code signing is no longer required for any release level, including stable:
  releases are published unsigned with mandatory SHA-256 checksums.
- The SignPath workflow, finalizer, artifact configuration, and the fail-closed
  `--require-signed` verification remain in the tree as an optional path that
  activates only when `SIGNPATH_ENABLED=true` is configured.
- Updated the signing policy, release verification, packaging docs, download
  verification, and the LCL cutover handoff to reflect the optional status;
  stale Qt-era signed-binary lists now name only `Zarya.exe`.
- Version contract bumped in lockstep: CMake, Pascal, PE metadata, and
  CLI `--version` all report `1.5.14`.
