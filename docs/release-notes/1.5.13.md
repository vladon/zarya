# Zarya 1.5.13

## Windows LCL cutover preparation

- Switched Windows CI/release jobs in `build.yml` and `release.yml` to the
  pinned LCL build/test/package flow (`prototypes/lcl/build.ps1`,
  `test.ps1`, `package.ps1`). Linux/macOS jobs stay on Qt/lib_ui.
- Windows CI artifacts are now verified in the strict
  `--windows-lcl-single-exe` mode: the ZIP root must contain exactly
  `Zarya.exe` and `Zarya.exe.sha256`, with no DLLs and no nested
  directories.
- Active SignPath configuration now signs only `Zarya.exe`; the signed
  package finalizer fails closed on a missing or invalid Authenticode
  signature instead of warning.
- Added negative packaging/signing contract tests: ZIP with an extra
  file, ZIP without the `.sha256` sidecar, and unsigned/tampered EXE all
  fail verification.
- Version contract bumped in lockstep: CMake, Pascal, PE metadata, and
  CLI `--version` all report `1.5.13`.
