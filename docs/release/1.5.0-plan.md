# Zarya 1.5.0 Plan

## Goal

Make the stable Xray system-proxy path work on KDE Plasma and strengthen the
regression coverage around platform proxy recovery and profile import.

The release theme is **stable desktop parity and reliability**. Experimental
TUN, helper, kill switch, installer, and app-update installation remain gated.

## User-visible outcome

- KDE Plasma users can enable Zarya's HTTP/HTTPS desktop proxy and restore the
  exact previous KDE proxy configuration on stop, safe exit, or startup
  recovery.
- Settings and logs identify the selected Linux desktop proxy backend and its
  limitations without claiming VPN/TUN coverage.
- Supported profile links and subscription entries have a consolidated
  regression matrix, including malformed-input and secret-redaction cases.

## Non-goals

- Promoting sing-box TUN, `zarya-helper`, kill switch, or app-update install to
  the stable channel
- Capturing traffic from applications that ignore KDE/KIO desktop proxy
  settings
- Shipping a production MSI, PKG, DEB, RPM, or AppImage
- Adding a new proxy protocol
- Changing the Windows static-Qt or mandatory `lib_ui` decisions

## Delivery order

Each item is one logical PR. Later PRs may depend on the earlier test seams, but
must remain independently reviewable and revertible.

### PR 1 — Deterministic Linux proxy tests

**Purpose:** Make desktop detection and command execution testable without
changing a developer's real proxy settings.

- Add an injectable process/configuration boundary for Linux proxy backends.
- Add deterministic tests for GNOME, KDE, unknown desktop selection, missing
  tools, command failures, and invalid proxy ports.
- Verify that snapshots and error messages contain no credentials or proxy
  profile links.
- Keep production behavior unchanged.

**Done when:**

- Tests run in Linux CI without a live GNOME or Plasma session.
- Tests cannot write to the runner's real desktop proxy configuration.
- Existing Windows and macOS builds remain unchanged.

### PR 2 — KDE Plasma proxy snapshot, apply, and restore

**Purpose:** Replace the current `KdeSystemProxyManager` placeholder with a real
stable-path backend.

- Confirm the supported Plasma 5 and Plasma 6 configuration/reload mechanism
  from current KDE sources before implementation; do not assume a legacy
  command or file format.
- Detect required KDE facilities and report the backend unsupported when they
  are absent.
- Snapshot every KDE proxy value that Zarya may overwrite, including proxy
  mode, HTTP/HTTPS endpoints, bypass rules, and automatic/PAC settings.
- Apply `127.0.0.1:<mixed-port>` for HTTP and HTTPS while preserving unrelated
  settings.
- Notify KDE/KIO that proxy settings changed.
- Restore the exact snapshot on stop, safe exit, and persisted startup
  recovery.
- Roll back to the snapshot if apply or reload fails partway through.
- Pass values as structured process arguments or API values; never build shell
  command strings.

**Done when:**

- Unit tests cover no-proxy, manual, PAC/automatic, partial failure, rollback,
  and restore-after-restart cases.
- Applying twice and restoring twice are safe.
- Zarya never reports the proxy as enabled after an incomplete apply.
- A manual Plasma 5 or 6 smoke confirms apply and byte-equivalent logical
  restore of the prior settings.

### PR 3 — Backend-neutral proxy UX and documentation

**Purpose:** Present KDE support accurately and remove GNOME/KDE special cases
from shared controller messaging.

- Replace hard-coded KDE partial/unsupported logging with backend-neutral
  status and error reporting.
- Show the detected backend and explain that desktop proxy settings affect only
  applications that honor them.
- Update EN/RU strings where user-visible text changes.
- Update README, stable scope, known limitations, and platform regression
  matrices.

**Done when:**

- GNOME, KDE, macOS, Windows, and unsupported Linux paths use consistent status
  semantics.
- Stable documentation no longer calls KDE unsupported.
- EN/RU translation checks pass.

### PR 4 — Profile import and subscription regression hardening

**Purpose:** Protect the stable protocol set while platform code changes land.

- Consolidate table-driven import coverage for VLESS, VMess, Trojan,
  Shadowsocks, Hysteria2, and WireGuard links.
- Add malformed encoding, missing required fields, IPv6 host, duplicate query
  key, unsupported option, and mixed-validity subscription cases.
- Confirm a failed subscription refresh preserves the previous profiles.
- Confirm test failures and diagnostics do not print credentials, private keys,
  subscription URLs, or raw links.
- Fix parser behavior only where a test demonstrates an incorrect or unsafe
  result; split substantive fixes into their own PR if needed.

**Done when:**

- Every stable protocol has valid, invalid, and redaction coverage.
- Existing persisted profiles remain compatible.
- Subscription failure is non-destructive.

### PR 5 — CI and release-readiness polish

**Purpose:** Make the new coverage a durable release gate.

- Run the Linux proxy and import/subscription suites in normal PR CI.
- Update GitHub Actions runtimes only where current actions emit deprecation
  warnings; keep changes mechanical.
- Add KDE apply/restore to the manual platform matrix.
- Run the full Windows static-Qt build, Linux/macOS builds, CTest, translation
  checks, packaging verification, and artifact secret audit.

**Done when:**

- All required checks pass on all three release platforms.
- KDE manual verification evidence is recorded in the release checklist.
- Portable artifacts remain reproducible in structure and contain no user data.

### PR 6 — 1.5.0 release

- Set version `1.5.0` on the stable channel.
- Write release notes and GitHub release draft.
- Complete the go/no-go checklist and documented regression matrix.
- Merge the release PR, tag the merge commit as `v1.5.0`, wait for release
  workflows, verify archive checksums/manifests, and publish the GitHub Release.

## Release gates

The release is blocked by any of the following:

- KDE apply can leave a partially modified configuration without rollback.
- Stop, safe exit, or startup recovery cannot restore the saved proxy state.
- Zarya reports proxy-on when the KDE apply did not complete.
- A regression affects the current Windows, macOS, or GNOME stable path.
- Profile/subscription tests expose secrets or a failed refresh loses profiles.
- Windows is not built with static Qt and mandatory `lib_ui`.

The release is not blocked by defects confined to correctly gated experimental
features, unless they affect recovery or the stable path.

## Deferred after 1.5.0

Choose the next product track only after 1.5.0 evidence is complete:

1. signed production installers and installed-layout migration;
2. signed-manifest app updater hardening before stable install enablement; or
3. production TUN/helper/kill-switch work with a separate threat-model and
   platform rollout plan.
